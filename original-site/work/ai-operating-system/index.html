The problem was continuity

AI tools are powerful inside one session and forgetful across sessions. Project decisions lived in old chats, a new model could repeat a rejected approach, and a confident answer about the code could already be stale. Normal chat memory was not enough for several active products being built across different tools and threads.

The vault is an AI-readable operating layer

The Obsidian vault is not merely a personal notebook. It is the canonical continuity layer: every project has a status dashboard and detailed panels; daily notes preserve the temporal story; durable pages hold architecture, decisions, risks, strategies and rejected paths; persona and operating rules teach a fresh model how to work with me.

Refer first. Work from evidence. Update the shared memory in the same turn.

Wikilinks turn those records into a navigable knowledge graph. A cold model reads the constitution, master index, working contract and relevant project panel—not the whole vault— and recovers the right context in a few targeted reads.

Project Brain connects intent to reality

Documentation explains why; it cannot prove what the current software does. Project Brain bridges that gap with local code graphs, repository history, product test commands and live evidence. Before code work, it generates a focused context pack containing the relevant intent, validated code path, recent changes, tests, file reservations and the required write-back destination.

VVDex Studio governs execution

Knowing the project and reading the code still does not define what an agent may do. VVDex Studio is the private control plane between grounded context and execution. A canonical contract drives the graph, allowed tools, human authority gates, harness cases, service evaluation, traces, evidence and reviewed memory. Claude, Codex/ChatGPT, VVDex or local models can work through the same boundary; the model does not own operational authority.

The public Agent Services Lab exposes selected deterministic proof across 37 base contracts. Customer systems, credentials, live traces and specialization remain private. Eval Hub is a separate independent layer for wider cross-product quality and safety baselines.

MNEMA is the product-memory layer

Project knowledge and product-user memory are different problems. MNEMA is the second one: an owned six-layer memory substrate for agents inside products. It supports working, episodic, semantic, procedural, core and outcome-causal memory with tenant-scoped retrieval on Postgres and pgvector. Conxto uses it for shared cross-agent context; the same foundation is designed to support MIRA, SEO Lab and VVDex workflows without mixing their domains.

The continuation loop

01 · Orient
Load identity, operating rules and the relevant project state
02 · Ground
Generate the task context and verify the code path against source
03 · Govern
Compile the graph, tools, authority and release rules inside VVDex Studio
04 · Exercise
Run clean, exception and failure cases through the harness
05 · Prove
Evaluate the contract and inspect the rendered or live result, trace and evidence
06 · Return
Review outcomes before writing durable knowledge to Vault or MNEMA

Built with AI, owned as a system

I developed this way of working across Claude and Codex, using each as an engineering collaborator while keeping the knowledge, rules, evidence and infrastructure under my own control. The value is not a particular model. The value is continuity: another capable model can enter the work without inheriting a blank slate or pretending old chat is truth.

Honest status

The operating loop is active and used across the portfolio. It is still being improved: older provider-specific wording is being generalized, freshness checks are being tightened, and MNEMA adoption is expanding product by product. The public counts above were audited in July 2026 and will grow as the system is used.
