Sara — a memory-native personal agent operating system.

I am building Sara as one persistent agent across my work—not another chat window. She combines durable memory, specialist agents, approval-gated actions and a Hey Buddy Mac body that can listen, speak, understand the active screen and operate verified tools.

The objective is continuity plus action

A useful personal agent must remember why work exists, understand what changed, choose the right specialist and act through tools without inventing success. Sara sits above career, personal operations, market research, software building and communications domains. Financial and trading systems remain structurally read-only; outward or irreversible actions go through owner approval.

Memory is retrieved, not blindly baked into weights

MNEMA provides six layers of runtime memory with scoped retrieval and provenance. The Obsidian operating memory preserves project decisions and history across Claude, Codex and future models. Stable behaviour belongs in model contracts; changing personal and project knowledge is retrieved at runtime so it can be inspected, corrected and kept private.

Specialists and parallel workers

Sara has six domain leads and a 25-agent tree covering career operations, personal systems, market research, building and communications. She can delegate to trained specialists or launch parallel researcher, analyst and coder workers, then synthesize their evidence instead of pretending one model did every job equally well.

Hey Buddy gives the agent a local body

The Mac body uses offline Whisper for speech recognition and offline Piper for speech. A floating interface shows listening, thinking, researching and speaking states. Its shared tool belt can inspect the current screen, control supported browsers and applications, enter text, use keyboard actions, scroll and recall or store memory. CDP and Playwright provide the browser layer; macOS Accessibility and Vision provide the current desktop layer.

An action is not “done” because a model says so. The tool must return verification and proof.

An owned open-weight model path

I did not want Sara's entire intelligence story to be “calls an AI API.” I built a private training lane around an open-weight Gemma base using MLX on Apple Silicon. The pipeline includes curated agent behaviour, tool schemas, safety contracts, accepted and rejected action traces, dataset records, saved LoRA adapters and repeatable evaluation reports.

Base
Open-weight Gemma model running locally
Training
MLX LoRA adapters trained on a MacBook Air
Data
Reviewed contracts, tool examples and accepted/rejected traces—not raw private-memory dumping
Evaluation
Recorded 9/9 on a nine-case held-out product-contract suite with the tuned adapter and explicit runtime contract
Runtime
Guarded local-first routing; stronger remote reasoning remains available for complex platform work

The nine-case result is a small internal contract test for identity, tool format, approval gates, screen truthfulness and trading safety. It is evidence that the training pipeline works—not a claim of general intelligence or a finished model.

Learning from actions

Each tool operation can record the instruction, resolved action, result, verification and proof. User feedback can label the action accepted or rejected. Those reviewed traces form a controlled data flywheel for later adapters, so training follows real corrections instead of synthetic success stories.

Honest status

Sara is an active research system, not a released product. The architecture, Mac body, specialist tree, memory rails, local training pipeline and verified tools exist. Long-horizon planning, robust recovery, a final custom voice, portable computer control and larger-model training on stronger GPU infrastructure remain open work.
