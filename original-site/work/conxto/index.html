Conxto — the AI Career Operating System

A live, multi-tenant career OS where seven specialist agents run a job search over one shared per-user memory — on top of two data engines I own outright. Launched at conxto.com on 2026-06-27. I'm the founder; I designed and built every layer end-to-end.

The problem

A job search is an operations problem wearing a motivation costume. Finding roles, scoring fit, tailoring a résumé, tracking a pipeline, following up at the right moment — each step is tractable, but they live in different tools that don't share state. Every "AI career tool" I found rented its core: jobs from someone's API, résumé checks from someone's checker. Rent the core and you inherit its costs, its limits, and its rug-pulls. So Conxto owns its core.

Seven agents, one memory

Conxto's specialist team is Identity, Operations, Market, Application, Strategist, Recruiter and Résumé Critic—and the deliberate constraint that makes them a team rather than six chatbots: they all read and write one shared per-user memory. MNEMA runs on Postgres + pgvector with per-user memory blocks; cross-agent recall is verified, and outcome→cause learning edges let results feed back into the next recommendation. Tell the Identity agent something once and the Recruiter already knows it.

Seven specialists run the career workflow. One shared memory ties it together.

Agents don't act unilaterally. Actions surface as approval-gated action cards — the agent proposes, you approve. And agents hand work to each other at real workflow moments, not on a timer: save → tailor → ready → applied → recruiter → strategist. Save a job and the tailoring path opens; mark it applied and the recruiter and strategist pick up the thread.

The proving ground became the product

Before Conxto had a product surface, I ran the same core idea against my own job search: specialist agents sharing an event history, a bi-temporal knowledge graph and an approval-gated dispatcher. That was not a second product—it was Conxto's proving ground. The patterns that survived became the agent and safety architecture described here; the separate experiment is no longer presented as another portfolio system.

Engine one: the Job Engine

Conxto pays nobody for jobs or résumés. The Job Engine ingests 17 live sources — Indeed, Greenhouse, Ashby, Arbeitnow, Himalayas, Jobicy, Lever, Adzuna, The Muse, Remotive, plus manual entry — plus an in-house harvester. Everything lands in Conxto's own Postgres: 25,000+ live jobs across 5,136 companies (live production, Aug 2026), full-text-search ranked, deduplicated, and liveness-checked so dead postings don't waste anyone's morning. The Discover deck scores fit grounded in matched-keyword evidence — you can see why a job scored what it did — with experience-level and geo-aware matching.

Engine two: the Résumé/ATS Engine

The second owned core is an in-house ATS scorer — RAKE keyword extraction, BM25 ranking, Porter stemming, pure Node, zero third-party checkers — plus 37 résumé templates with live PDF preview and DOCX export. Tailoring is honest by construction: every tailor produces a real before→after ATS re-score and a diff of what changed. No "94% match!" theater. If the score didn't move, the product says so.

Public product: Conxto Résumé Studio

I opened the résumé foundation as a standalone public product at conxfolio.com. It is free, requires no login, adds no watermark and does not ration documents or downloads. People can build or import a résumé, work through guided editing, switch among 37 templates, export PDF or DOCX, and run an honest ATS check. Résumés stay in the browser rather than being attached to an account.

The boundary is deliberate: Résumé Studio is the open utility; Conxto is the connected career operating system for persistent job discovery, tailoring, applications, follow-ups and agent workflows. The public product is live, while its search-discovery and content growth remain active work.

Tracker and auto-submit

The Tracker is the mobile-first hub: 7 stage lists, a kanban pipeline board, follow-up signals, and receipts for what happened when. It was redesigned on 2026-07-02 and live-verified at 390px — 0 overflow, 0 console errors. Auto-submit drives a real browser to fill applications across 7 ATS platforms (Greenhouse, Lever, Ashby, Workable, Recruitee, Teamtailor, iCIMS). It is approval-gated with screenshot receipts and currently runs in dry-run mode — nothing sends without explicit approval.

Built like production, not a demo

Multi-tenant from day one: fail-closed per-user context, tenant isolation, and end-to-end audits run against a prod-schema clone before changes ship. The product rule that governs all of it: honesty as a feature — every number in the UI is a real count or a dash. Nothing is fabricated to look busy.

What I'd tell another builder

Own the data engines that your product depends on — the harvester and the scorer were harder to build than the agents, and they're the moat. Gate every agent action behind human approval and attach a receipt; trust is the actual product. And make honesty a rendering rule, not a value statement: when the UI can only show a real count or a dash, the whole system stays true.
